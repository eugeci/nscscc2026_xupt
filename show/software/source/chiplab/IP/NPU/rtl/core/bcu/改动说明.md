1.2 架构级隐患修复：读循环嵌套顺序反转 (Outer: Pixel -> Inner: Cin)
在本次大重构中，我顺手解决了一个原架构的物理极限隐患。
之前我们是外层扫 Cin，内层扫 (x, y)，这要求 NPU 内部有整张图的显存。但实际上您的 NPU 只有 512-bit 的 PSUM。
在 bcu_v2 中，我将读取引擎的循环彻底反转：外层扫像素位置，内层切通道。现在 BCU 会把同一个坐标 (0,0) 的所有通道数据全部喂给 NPU 算完，再移动到 (0,1)，这与硬件底层的累加器完美契合！
1.3 LBP 初始化直写接管 (响应 C 组要求)
为了满足 C 组 Sequencer 启动时的物理直写需求，我将提供一个独立于 BCU 之外的顶层路由网格 (Memory Crossbar)，通过 i_seq_pc == 0 作为最高优先级强占令牌，剥夺 NPU 的写使能，将地址总线直接交给 LBP 控制器。

二、BCU v2.1 — Step 14.1a 升级（2026-04-27）

2.1 地址宽度调整（适配新存储拓扑）

为了同时支持 layer-0 LBP 输入（19200 像素，需 15b 地址）和 layer-1+ 激活存储（fm_bank_array 8K 深，13b 地址），BCU 的地址端口分别调整：
- `o_sram_rd_addr` : 14b → **15b**（高 2 位仅用于 LBP buffer 寻址；fm_bank_array 取低 13 位）
- `o_sram_wr_addr` : 14b → **13b**（写仅落盘到 fm_bank_array，不涉及 LBP buffer）
- 内部 `r_wr_addr` 寄存器同步收窄到 13b。

2.2 修复隐含 bug

原 14b 读地址（max 16384）无法覆盖 layer-0 LBP 的 19200 像素扫描。本次扩宽到 15b 后，layer-0 完整帧可被正确扫描，与 sequencer 端 `o_lbp_wr_addr` 同步扩宽。

2.3 BRAM 预算节约

BCU 配合 fm_bank_array 的 16K→8K 瘦身：在 NPU 侧 fm M4K 占用从 1024 降至 552（节约 46%），为 1200 M4K 板卡预算腾出空间。

# NPU IP

Standalone RTL, scripts, parameters, documentation, and cocotb tests for the
FPGALightFaceNet-oriented NPU IP.

## Status

Current baseline: extracted standalone `npu_ip` tree, verified on 2026-05-31.

- `npu_top_with_dma` end-to-end cocotb: `5 PASS / 0 FAIL`
- Single-frame bbox: `[9, 0, 0, 1, 5]`, bit-true against Python golden
- Three-frame continuous run: all frames output `[9, 0, 0, 1, 5]`
- Parameter hex offline check: `217` weight groups and `18` bias groups match
- Calibrated quantization baseline (2026-06-12): full validation split
  `9997` samples, quantized confidence accuracy `92.12%`, quantized positive
  avg IoU `0.6122`, quant-vs-float output MAE `0.00893`.

## Directory Layout

```text
npu_ip/
├── rtl/
│   ├── core/        # npu_core_top and compute/memory submodules
│   ├── preproc/     # rgb2y/preproc and current ROM-DMA wrappers
│   └── wrappers/    # reserved for SoC/AXI wrappers
├── sim/             # cocotb tests, Makefiles, directed microcode hex files
├── scripts/         # quantization, microcode, and parameter verification tools
├── params/          # model weights and generated NPU parameter image
├── filelists/       # RTL filelists for SoC/Vivado integration
└── docs/            # design, progress, and SoC integration notes
```

## Key Tops

| Top | Purpose |
| --- | --- |
| `npu_core_top` | Stable compute core. External logic must provide LBP pixels and weight/bias loading. |
| `npu_top_with_dma` | Current verified wrapper: `npu_core_top + weight_rom_dma`, with `params/npu_params.hex` compiled into ROM. |
| `npu_preproc` | RGB888 to LBP preprocessing path. |
| `npu_full_chain` | Full RGB888 input to bbox output verification wrapper. |

For a Xilinx SoC, prefer keeping `npu_core_top` unchanged and adding AXI logic
around it in `rtl/wrappers/`. The current `weight_rom_dma` is a verified ROM
loading wrapper, not the final DDR/AXI master.

## Parameters And Microcode

- `params/fpga_face_net.pth`: source PyTorch weights used by Python golden and export scripts.
- `params/quant_config.json`: calibrated quantization contract generated by
  `scripts/quant_calibrated.py`. Python golden and microcode generation prefer
  this file when present.
- `params/npu_params.hex`: blocked INT8 parameter image consumed by `weight_rom_dma`.
  Simulation Makefiles pass this path through the `NPU_PARAMS_HEX` compile macro
  because older VCS releases do not reliably override string parameters with
  `-pvalue`.
- `sim/microcode_face.hex`: FaceNet layer descriptor ROM image used by current Makefiles.
- `sim/microcode_*.hex`: directed-test microcode files.

Regenerate when model topology or weights change:

```bash
cd npu_ip
python3 scripts/compile_model.py --config configs/facenet_lbp_v1.json --eval-samples 0 --device cpu
```

The compiler wraps the calibrated quantization, microcode generation,
descriptor generation, BSP descriptor header sync, and consistency checks. It
also writes `params/npu_compile_manifest.json` with commands, artifact hashes,
ROM word count, layer shifts, and quantization metrics. Use a dry run before
overwriting artifacts:

```bash
cd npu_ip
python3 scripts/compile_model.py --config configs/facenet_lbp_v1.json --dry-run
```

For stage-by-stage debug, the compiler command above is equivalent to:

```bash
cd npu_ip
python3 scripts/quant_calibrated.py --calib-samples 2048 --eval-samples 0 --batch-size 128 --device cpu
python3 scripts/gen_microcode.py
python3 scripts/gen_descriptors.py
cp scripts/npu_desc.h ../../../sdk/software/bsp/include/npu_desc.h
cp scripts/npu_desc.hex sim/npu_desc.hex
python3 scripts/verify_npu_params_blocked.py
python3 scripts/check_desc_match.py
```

Current compiler support is intentionally scoped to `facenet_lbp_v1`
(FPGALightFaceNet, 120x160 LBP input) and `mnist_lenet_v1` (PPQ_Mnist LeNet,
28x28 MNIST input staged through the current 160x120 frame loader). Compile the
MNIST target with:

```bash
cd npu_ip
python3 scripts/compile_model.py --config configs/mnist_lenet_v1.json
```

The generated SoC parameter image must match the software-selected model:
FaceNet model 0/1 uses `params/npu_params.hex`, while MNIST model 2 uses
`params/mnist_lenet/npu_params.hex`. See `docs/NPU_MODEL_COMPILER.md` for
inputs, artifacts, board validation, and the path to adding another CNN target.

Run a single real-image reference inference:

```bash
cd npu_ip
python3 scripts/run_real_image_ref.py img_640x480.jpg --lbp-mode intended --quiet-layers
```

The training contract uses 120x160 LBP images divided by 255.0, and the model
outputs `{Conf, Cx, Cy, W, H}`. Use `--lbp-mode intended` for training-compatible
LBP bit order. The default `--preproc rtl-bilinear` matches the aligned RTL path;
`--preproc point-sample --lbp-mode legacy-rtl` is only for legacy diagnosis.

## Verification

Run the current NPU + ROM-DMA end-to-end test:

```bash
cd npu_ip/sim
make -f Makefile.weight_rom_dma_e2e
```

Run the same regression with VCS:

```bash
cd npu_ip/sim
SIM=vcs make -f Makefile.weight_rom_dma_e2e
```

Validated on VCS O-2018.09-SP2: `TESTS=5 PASS=5 FAIL=0 SKIP=0`
(2026-05-31). The VCS flow uses absolute `MICROCODE_FILE` and
`NPU_PARAMS_HEX` compile macros; this avoids relying on string parameter
overrides and keeps `$readmemh` paths stable across simulator working
directories.

Useful shorter checks:

```bash
cd npu_ip/sim
make -f Makefile.face
make -f Makefile.weight_rom_dma
make -f Makefile.preproc
make -f Makefile.conv_engine
```

Generated simulation output should not be committed. The Makefiles provide
`clean` targets, and common products are `sim_build*`, `results*.xml`, `*.vcd`,
`*.fst`, and `__pycache__/`.

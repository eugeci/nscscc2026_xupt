# 闭环演示硬件待确认清单

本文只列必须在真实板卡、摄像头、机械臂和工作台上完成的事项。软件工具、
文件格式和合成测试可以离线完成，但下列参数不能根据代码、旧装置数据或
手机摄像头推测。

## 2026-08-15已完成的板上复测

- Linux设备树内存范围已限制为 `0x00000000-0x077fffff`，顶部8 MiB不再被
  Linux分配；修复前摄像头DMA会覆盖initramfs中的动态库；
- buffer 0和buffer 1各成功短时采集一帧，均为614400字节，帧计数分别为5和10；
- buffer 0经串口取回后SHA-256与板端一致，并成功转换为640×480 PNG；画面和
  RGB565LE颜色通道正确；
- 短时采集前后 `/lib32/libm.so.6` SHA-256一致，采集工具退出后DMA自动关闭；
- XNPU轮询和IRQ推理均通过既定校验，IRQ 23计数由0增加到1；
- Linux已识别 `eth0` 并在启动时自动配置为 `192.168.1.101/24`；主机连续
  5次ping零丢包，614400字节文件经HTTP传输后SHA-256一致；网卡IRQ 18有计数，
  `carrier=1`，收发错误、丢包和overrun均为0；
- 标定样例同时通过PC验证和SoC端 `--check-calibration`。样例仅验证流程，不是
  当前机械臂的实测标定数据。

H01仍需按下述标准完成每个buffer至少100帧的长期完整性测试；H04以及真实
相机、桌面和机械臂标定仍未完成。本次没有发送任何机械臂运动命令。

## 使用规则

- 每项必须记录日期、操作者、bitstream提交、内核提交和ESP32文件版本；
- 原始图片、CSV、标定文件和终端日志必须保留，不能只记录最终数字；
- 任一安全项未通过时，`calibration.ini` 必须保持 `validated=0`；
- 摄像头、底座、桌面或机械结构变化后，按“失效条件”重新执行相关项目。

## H01：VDMA乒乓缓冲选择

需要确认：

- `0x07c00000` 和 `0x07d00000` 是否都持续包含完整640×480 RGB565帧；
- 当前S2MM状态是否能可靠指出正在写入的buffer；
- 两个buffer的更新顺序和帧计数关系。

现在不能确定的原因：当前CONFREG只公开两个地址和总帧计数，没有定义活动
写buffer编号。`visionarm-capture`因此采用短暂停DMA后复制的保守方案。

通过标准：两个buffer分别采集至少100帧，无半帧、撕裂和跨帧拼接。确认
状态位后才能实现不停DMA的非活动buffer选择。

## H02：CPU读取DDR的一致性

需要确认：VDMA写DDR后，CPU通过 `/dev/mem` 是否总能读到最新数据，是否存在
cache未失效造成的旧帧。

方法：拍摄帧间差异明显的计数牌或移动标记，连续保存原始帧，对比硬件帧
计数与文件内容。如果出现重复旧帧，应增加正式摄像头驱动和DMA同步，不能
继续依赖 `/dev/mem`。

## H03：实际像素格式和几何方向

需要确认：

- DDR字节序是否为RGB565LE；
- R/G/B通道是否正确；
- 图像是否水平或垂直翻转；
- 320×240到640×480的缩放是否与寄存器说明一致；
- 有效画面是否存在黑边、裁剪或行填充。

结果写入：采集元数据、转换工具默认值和标定文件版本说明。

## H04：OV5640成像稳定性

需要固定并记录镜头焦距、支架姿态、工作距离、曝光、白平衡和演示照明。
自动曝光/白平衡导致颜色阈值漂移时，需要锁定传感器参数或扩大训练数据。

通过标准：固定积木连续100帧的候选框中心和面积波动满足控制死区要求。

## H05：相机和桌面标定

必须使用最终安装的OV5640和最终640×480 DDR图像采集：

- 15～30张不同姿态棋盘格图片；
- 标定板真实内角点规格和方格毫米尺寸；
- 桌面至少4个不共线实测点，并额外保留检查点；
- 桌面高度和积木高度。

手机只能帮助测量或复核，不能替代OV5640最终参数。

## H06：限位极性、方向和最大行程

逐轴确认GPIO36/39/34的未触发/触发电平、`DIR_TO_LIMIT`方向、退出回差步数、
回零最大步数和可安全使用的另一端软件行程。

这决定 `max_x_steps/max_y_steps/max_z_steps`。在三项均为实测正数以前，电脑
验证工具不会把标定文件设为 `validated=1`。

## H07：工作零点与重复精度

从机器限位零点以100步为单位移动到安全抓取姿态，记录三轴偏移；完整回零
后重复3～5次，测量夹爪标记像素误差和实际毫米误差。

旧 `go_to_origin.py` 的固定步数不属于当前硬件有效数据。

## H08：机械臂动作应答通路

需要确认板卡引脚是否能把ESP32 GPIO4 TX接回FPGA，并确定电平、约束管脚和
空闲电平。当前RTL没有UART RX，Linux不能确认 `ACK/DONE/ERR/POS`。

在该通路完成前，自动采样只能采用固定保守等待并同时监控ESP32 USB串口；
不能宣称具备可靠的无人值守自动标定。

## H09：X/Y/Z图像雅可比与Z/Y耦合

在多个工作区位置分别执行正负100步，保存运动前后夹爪标记坐标。当前Z轴
每3步会附带1步Y轴动作，实际位移必须包含在采样中。

结果写入 `alignment_axes`、`jacobian`、拟合误差和有效工作区域。若不同区域
差异过大，需要分区矩阵，不能使用单个全局比例。

## H10：夹爪安全PWM与抓取条件

需要实测不会产生齿轮异响或堵转的开合PWM范围、动作时间、可夹积木尺寸和
释放位置。现有30%/70%只是保守测试位置，不是最终抓取参数。

没有电流或力反馈时，抓取成功必须通过视觉复核，不能仅凭“close命令已发”。

## H11：相机可见性和遮挡

确认夹爪标记在搜索、对准、接近和夹取各阶段是否可见；确认机械臂不会遮挡
积木导致控制误判。如果接近阶段不可见，需要改变相机位置、增加标记或设计
阶段性开环安全距离。

## H12：真实积木数据集

必须采集最终相机、照明、桌面和实际积木下的数据，包括不同位置、旋转、
距离、部分遮挡、空背景、相似颜色和非目标物体。没有这些数据只能验证训练
流水线，不能生成可用于演示验收的 `blocks_v1.xnpu`。

## H13：Z接近、桌面高度和抓取阈值

单目相机无法从未知物体单帧可靠恢复Z。需要实测桌面高度、各类积木高度、
安全接近距离、候选框面积/尺寸与距离关系，以及Z/Y耦合补偿。

在完成前，自动程序只能启用XY对准，不能启用APPROACH和GRASP。

## H14：急停和故障恢复

需要验证物理断电方式、串口STOP延迟、限位异常、XNPU超时、摄像头丢帧、
目标丢失和机械臂失步后的行为。物理电机断电必须独立于Linux和ESP32软件。

## 硬件复测推荐顺序

```text
H03像素格式 → H01/H02帧完整性 → H04成像稳定性
→ H06限位与行程 → H07工作零点 → H05相机/桌面标定
→ H09机械臂视觉标定 → H10/H11夹爪与遮挡
→ H12模型数据 → H13接近抓取 → H14故障验收
```

H08动作应答通路可以与前述测试并行确认，但在无人值守闭环前必须完成。
